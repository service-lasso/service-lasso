## 1. Decision and invariants

Recommend **an original native CoreFinisher construction host outside the CoreCreator/Core death domain, with the original bootstrap and managed resource finishers outside target containment**. CoreFinisher (H) is the actual native constructor: it creates the original CoreCreator admission process (C), original full Node Core (N) and bootstrap (B), preserving each native creation result immediately. Bootstrap creates original managed finisher (M); M creates the target. CoreCreator is the separately observed native admission/lifetime process, not a replacement name for H. H holds original C/N lifetime objects, and transfers reduced originals to B/M before their protected acquisition gates. C/N death denies all further admission and requests closure; it never kills H/B/M. M owns all its actual CLR files, HMAC, environment, exceptions, native target/Job/stream observations and target issuance ledger. B owns its actual pending I/O, original managed child, BCrypt/environment/image/directory resources. H owns its actual constructor inputs, grants, Core/creator/bootstrap birth and stream observations. All three survive both C and N death and finish or retain their originals without a reconstructed owner.

H is launched through the independently authenticated installed native source/actor authority before C or N creation; it is not spawned inside their kill domain. H birth itself has no C/N-dependent protected acquisition. Unsupported inherited Job/cgroup topology denies before any protected launch acquisition: deployment must actually place H/B/M outside C/N and target death containment. H is a bounded construction/finisher host for original invocations, not a persistent service broker permitting target adoption or continued service execution after C/N death. The original target lifetime remains tied to C and N. No native host, thread, CLR runtime, private ledger or retained process receives an accounting exemption; all belong to the selected finite whole-runtime B0/B2 measurement and owned domains. H and its admitted source/provider profile are a proposed role with missing real identities/assets, not an activated service.

This deliberately introduces a new native constructor boundary. Current bootstrap and managed code do not implement it. An in-process addon which merely duplicates Node's self handle would bind a process but would not establish authority over its loaded JavaScript, global dependencies or source provider. It is not the recommendation. A native host still needs the actual authenticated installed-source provider described below; its name or executable digest alone cannot authenticate Node's executed source.

Normative invariants:

1. A grant exists only for a native-constructor-created original Core process and one immutable workspace/service/invocation generation. No late `OpenProcess`, PID/path/registry claims, role flag or `authenticated:true` can construct it.
2. No target executes until source/image bindings, original peer enrollment, capability grant and containment assignment are recorded. Owner death or uncertain owner observation closes the run gate.
3. The original object owner records every acquisition, original API result/error/exception, retirement attempt and closure observation before later work. Failed or unknown dependent closure keeps the same actual owner and resources alive; safe independent later releases still run once.
4. Workspace shutdown enumerates every ownership root, including finalizer-only and restart-only records. It never affects another workspace or publishes an internal path-bearing key.
5. A settled Promise, root exit, provisional terminal, empty Job count, successful termination call or closed stdin is not complete process/Job/stream/input/resource closure.
6. Absolute caller deadlines, native inspection policy, original protected assertions and the original eight packaged cleanup attempts are unchanged. A deadline produces failure/unknown, never successful closure.

## 3. Constructor, grantor and authenticated source boundary (N1)

### 3.1 Constructor API and origin

The proposed native `CoreFinisher` executable has no public mint-from-PID interface. At its native startup, before it creates C or N, H holds approved installed image/directories and independently authenticated provider configuration, verifies the actual issuer/profile/realm and actor-to-workspace policy, and creates its private native original-owner roster. Native CoreCreator C is an admission peer created by H; it can submit validated transport actor, permission/confirmation/idempotency and approved workspace/plan references. C owns no original target termination right and cannot select issuer/grantor objects. H independently validates every request and never treats C's claims or an opaque reference as source authority.

The host uses the approved full Node image and preserves the human's finite N2 decision: full Node22.23.2/full ICU/public library/Buffer/API, complete owned accounting and a measured finite whole-runtime replacement budget for domain0/domain2. The selected choice is recorded in `docs/decisions/NATIVE-RUNTIME-N2-WHOLE-CONTRACT-CHOICE.md` in the parent-supplied CLI source input, subsequent explicit human choice dated 2026-10-05. B0/B2 remain UNKNOWN and Q0/Q2=34359738368 (32GiB) are qualification availability ONLY, not production B or allocated arena; service1MiB, combined store4MiB and Core128MiB are separate unchanged domains. This proposal supplies neither a numerical replacement cap nor a host exemption/extra pool. All H/C/B/M/native monitor/retained owner allocations are counted with the original whole-runtime measurement; no additional hidden host pool. The existing Core1643 entire6C architecture remains NO_GO and global T+S remains UNSELECTED.

The constructor must resolve and bind the complete governed Node/Core/native source namespace and actual global T/S dependencies through an authenticated source-authority provider, with original held input custody and dynamic imports/support bytes covered by that route. Those providers are missing, not an implemented “existing” authority. It must not replace the human's decision with an 8 MiB full-Node cap, a Node facade, guessed module list or extension filter. Finite N2 is a budget contract choice, not proof that Node's entire execution graph is authenticated. Missing T/S/global or actual source authority blocks constructor activation before Core creation; this proposal does not select T/S or supersede their whole review.

`ConstructCore(approvedInstalledBinding, workspaceAuthority, admittedActor)` is executed only by H. Before protected launch inputs are acquired, H records its actual original C creation, immutable birth and installed binding; then it creates N suspended on Windows or with atomic clone3 pidfd and pre-exec gate on Linux, storing the original result before observation allocation. H is sole original Core issuance owner. H creates `CoreOwner` in its native roster from original C/N/H objects, workspace identity, provider policy references, source binding, nonce, version and generation; it enrolls N and opens its gate only after C/N/H original observations are live and known. C death before N birth denies N creation; death during/after N birth closes its gate and H issues the original Core compensation once, with separate wait/reap/stream outcomes. H owns all constructor failure/retention objects and stays alive after C/N death. H startup or genuine H death is a different finisher-owner-loss fault: it is never reported as same-owner retention or reconstructed successful cleanup. Actual installed H/C policies/assets and actor/source providers remain prerequisites.

The internal Core-facing API is `GrantLaunch(CoreSession, WorkspaceAuthority, ServiceAuthority, admittedPlan)` returning an opaque reference usable only on that session. JavaScript cannot deserialize, clone or rebuild authority; native code performs roster lookup and full context comparison on every call. References are not public service IDs or bearer strings transferable between Core sessions. There is no public constructor accepting an owner PID, signing identity, hash, path or privileged actor flag.

### 3.2 Windows transfer and peer authentication

H creates bootstrap B suspended from its original held verified image/directories with `bInheritHandles=FALSE`, outside all C/N kill domains and target containment. It records original B process/thread creation immediately. H retains its originally created B process object with the process-wide rights needed for host-pull transfer; this privileged right stays only in H. B and M receive `SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION` noninheritable duplicates of original N, C and H lifetime objects. They receive no `PROCESS_DUP_HANDLE`, terminate, VM/write or token rights on H/C/N. `DuplicateHandle` uses original H-owned source and created recipient objects, explicit desired reduced rights, FALSE inheritance and options zero; never `DUPLICATE_CLOSE_SOURCE`. Successful target-local slots and original API results enter H's original grant roster before publication. H process-wide duplication privilege on its own originally created B and its validated original M transfer handle is explicit TCB authority of the independently admitted native constructor, not called an isolated object capability.

An H-created local named pipe uses first-instance creation, rejects remote clients and applies the actual admitted profile DACL. Its unpredictable name is routing only. B can run enrollment code before protected image/file/HMAC/environment acquisition and cannot create M or target before enrollment. H obtains OS pipe client PID/token and compares with its original created B object, birth, still-live state and installed source/profile. PID is only a cross-check; no PID open. H supplies B's already-transferred reduced N/C/H slots and challenge on that authenticated channel. B checks the actual server against its original H observation and independently installed H image/policy. H, not C, remains the channel server and grants publisher after C death solely for failure/closure observations; no new run admission is legal. A forged manual launcher, source policy mismatch or unknown original lifetime denies before protected resources.

Before managed creation, enrolled B retains its original N/C/H observation slots and full package inputs, and requests H to reserve an immutable managed birth/grant record. B is original M creation/compensation owner; it creates M suspended outside C/N/target kill domains and records the original process/thread, native create/error and birth before later work. B sends only a `CHILD_CREATED` notification identifying its two local original process/thread slots. H pulls an H-private managed process transfer handle (`PROCESS_DUP_HANDLE | SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION`, no terminate/VM/token rights) and thread observation (`SYNCHRONIZE | THREAD_QUERY_LIMITED_INFORMATION`, no resume/terminate rights) using `DuplicateHandle` from H's already-held original B process object; B never receives duplication rights into H. The pull is process-wide privilege exercised by H and must validate the immutable reserved creation, actual type, original B context, exact M birth/image/source and matching original process/thread relationship before grant publication. B must keep those original slots live and unmodified through pull/ack; slot reuse, foreign type/child, changed birth or failed validation denies and retains original B create primary. H never treats the numeric notification as authority. H duplicates reduced N/C/H and B lifetime observations into the validated original M; source/profile/pipe peer checks bind exactly that child. B resumes M into enrollment only after complete publication acknowledgement, and no M protected acquisition is permitted until its own enrollment succeeds. Before enrollment opens, B can compensate the original suspended/no-protected-resource M once; after enrollment commits B cannot terminate M, which must survive to finish/retain its originals. The commit is the closed OWNER_COMMIT/OWNER_COMMIT_ACK handshake: B records its irrevocable no-terminate phase before ACK; H publishes M enrollment only after observing that exact phase, and M does not acquire before the authenticated grant and original lifetime recheck. H similarly records its own irreversible NO_TERMINATE_B phase before resuming B into enrollment. M cannot run enrollment before the original observation slots exist; successful transfer followed by uncertain ACK retains those exact transferred originals. Lost commit acknowledgement retains the conservative enrolled/no-terminate phase, never reopens compensation. H compensation likewise never terminates an enrolled B or M.

This avoids transient inheritable Core/creator capabilities in Node or broad handle inheritance into arbitrary concurrent children. For target standard streams only, managed uses `STARTUPINFOEX` with `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, explicit inheritable duplicates of its three approved stream handles and TRUE inheritance, closing temporary duplicates once the original create result is recorded. No owner/grant/Job/image/directory/policy handle is on the target list. All handle-list creation/attribute failures retain original outcomes and deny create; no fallback to inherited-all. General Core child creation is routed through the constructor or explicitly outside this protocol with no cleanup guarantee; a normal entrypoint cannot silently bypass the creator.

Every enrollment challenge includes protocol, original Core/creator/peer birth, workspace native identity, safe service identity, immutable invocation nonce/generation and held source/asset digests. Native grant records and live channel custody authorize enrollment; challenge strings, hashes and paths alone do not. Challenge replay, duplicate grant, foreign generation, unknown slot, extra handles, identity mismatch, incomplete binding and original-owner signal deny admission. Once consumed, a grant cannot be reissued for the same creation under a replacement peer.

### 3.5 Closed native grant protocol

This proposed private v1 codec is a closed binary grammar, not a JSON parser or public API. Native implementation and independent whole codec/source review are still UNRUN. All integers are unsigned little-endian except the explicitly signed result field; no padding, pointers, implicit platform structs, trailing bytes, text, arbitrary extension or optional field. Header is exactly 64 bytes:

| --- | --- | --- |
| 0 | 4 | ASCII `SLO1` |
| 4 | 2 | version=1 |
| 6 | 2 | message kind 1–18 below |
| 8 | 4 | total bytes = 64 + exact body length |
| 12 | 4 | flags=0 |
| 16 | 8 | per-channel per-direction sequence starting 1, strict next; overflow denies |
| 24 | 8 | immutable nonzero invocation generation |
| 32 | 16 | original invocation opaque nonce, exact roster match |
| 48 | 1 | sender role: H=1, B=2, M=3, N=4, C=5 |
| 49 | 1 | recipient role, authenticated channel match |
| 50 | 1 | sender state: C0=0, C1=1, L0=2 through L11=13, LU=14 |
| 51 | 5 | zero reserved bytes |
| 56 | 8 | opaque local session roster reference; channel/context checked, never bearer authority |

Every message below has a fixed body. `Ref` is an 8-byte nonzero opaque roster reference, `Digest` and `Challenge` are 32 bytes each, `Birth` is an 8-byte platform-bound original birth association; original complete kernel/native birth remains private in owner. `Mask` is a u32 fixed bitmask; undefined bits deny. `Outcome` is 32 bytes in this exact order: namespace u8, disposition u8, operation u16, original site ID u32, acquisition ordinal u64, signed original result i64, original status u32, reserved zero u32. Namespaces are VALUE=0, WIN32=1, NTSTATUS=2, HEAP=3, ERRNO=4, CLR=5. Disposition is KNOWN_OK=0, KNOWN_FAIL=1, PENDING=2, UNKNOWN=3; CLR carries private exception reference in result (not serialized object), status=0; Heap has status=0 (no invented last-error); NTSTATUS preserves raw 32 bits and result; Win32/errno status is the immediate original value when the API contract supplies it. This transport projection cannot replace the owner's full original object/result ledger. Operation IDs are CREATE=1, TRANSFER=2, ASSIGN=3, RESUME=4, WAIT=5, EXIT_QUERY=6, KILL=7, READ=8, WRITE=9, CANCEL=10, RELEASE=11, SOURCE_BIND=12, RETAIN=13. Unknown operation/site or invalid namespace pair denies; source-qualified site roster is installed with the exact asset, not caller text.

`Slot` is 24 bytes: role u8, OS u8 (Windows=1/Linux=2), rights class u16, ordinal u32, recipient-local value u64, transfer Ref u64. Closed observation slot order for B is N-observe(1), C-observe(2), H-observe(3); for M it is those plus B-observe(4). Class1 is Windows SYNCHRONIZE|PROCESS_QUERY_LIMITED_INFORMATION or Linux profile-limited pidfd observation; no terminate/duplication rights. Transfer Ref binds original successful issuer operation and exact recipient; zero/local-invalid values, duplicate roles/ordinals, wrong order/type/rights or uncommitted transfer deny. In Windows the value is the actual already-duplicated recipient slot, not a handle inherited from frame bytes. It does not define a runtime or native roster cap. No message can change original generation, manufacture resource authority or restart a revoked gate. Channels are H-centered original native sessions; N/C/B requests enter H, and any authorized relay to M is a new H-sender frame with its own direction sequence, not a spoofed sender header. Policy issuer/profile/realm/service identifiers are not transported as free text; references resolve only against H's original independently authenticated installed policy/admitted manifest roster. Partial frame, incomplete pending I/O, wrong ancillary slots or lost publication remains original failure/unknown; no retransmission of effect/grant, timeout terminal or replacement channel. A duplicate message is rejected, not a retry. Frame parsing begins only after native original OS peer checks. Invalid unauthenticated peers receive no private denial detail. All header/body fields and private projections remain inaccessible to public API/Audit/Inbox/MCP.

### 3.6 Survival and containment topology

No creator-owned outer Job contains B or M. On Windows M holds the target-only original Job with kill-on-last-close and no breakaway, assigns original target suspended, and is the only process with an explicit termination handle. H/C/B do not hold a target kill Job duplicate or target PROCESS_TERMINATE right. B/M are not descendants in a death-kill domain whose last close by C/N/H would kill their original resource owners. Inherited parent Job restrictions, nesting, unsupported creation or profile restrictions must be checked before protected acquisition and deny; this proposal does not mutate host policy. Linux uses M-owned target-only cgroup; H/B/M are outside it, and realm/delegation denies peer kill authority. No creator/child cgroup.kill arbitration exists.

The no-terminate enrollment commit protects original B/M resource birth: H may compensate B only while its run/enrollment gate proves no protected B resource acquisition is possible; B may compensate M only before the corresponding commit. Once the owner can acquire, upstream keeps its original child/inputs and requests downstream finish, regardless of lost ACK. Revocation is monotonic before and after acquisition. On C/N death after NO_TERMINATE commit but before peer enrollment, surviving H may complete only the already-reserved original observation/denial publication and B may resume M into enrollment-only closure, never into resource/target acquisition. M observes the original death/revoked grant, records denied/no-target and finishes its enrollment resources. If transfer/observation itself failed or is unknown, original suspended child and all owners remain retained unknown; they cannot be called successfully cleaned. There is no grant retry, pre-enrollment termination after commitment or reliance on an absent ACK to undo commitment. If C/N die during an original create native call, the surviving issuing owner records its actual return/error, then compensates original unassigned child or asks enrolled owner to finish; it never assumes create failed, reopens PID, resumes, or discards a partially published original. ## 12. Native API sources and claim limits

Official primitives support the proposed mechanics, not Service Lasso implementation or qualification:

- [Microsoft DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle): original process rights, explicit desired duplicate rights and target-local values; no reliance on late OpenProcess recommendation.
- [Microsoft UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute): explicit handle-list inheritance; no pseudo handle in that list.
- [Microsoft GetNamedPipeClientProcessId](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid): peer PID is a cross-check, not independent source or actor authority.
- [Linux pidfd](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) and [fork](https://man7.org/linux/man-pages/man2/fork.2.html): process descriptors and inherited FD behavior; construction recommends atomic clone3 pidfd rather than request PID acquisition.
- [Linux parent-death signal](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html): creator-thread/registration/exec credential caveats explain rejection as sole authority.
- [Linux kernel cgroup-v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html): delegated containment/kill/populated primitives; actual delegation and escape restrictions remain qualification prerequisites.

The trust policy, source-provider completeness, native constructor semantics and whole closure behavior are recommended new requirements, not facts asserted to exist in current source. Documentation/source byte checks do not execute or qualify them.
