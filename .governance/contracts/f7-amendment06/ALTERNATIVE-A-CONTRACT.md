# A: immutable durable prefix and independent original terminal custody

This is the concrete ordinary-software candidate requiring the explicit changed acceptance clause in SELECTED-DISPOSITION. It does not satisfy universal durable terminal acceptance and must never be labelled such. All original row actions, once-only crypto, original managed/native custody and finite reservation proof remain mandatory.

## Original receiving inputs and ownership

The future original ROOT creator receives authentic original source/issuer bindings, actor/resource/key/grant catalogs, nine row reservations, original queue/state/stack/readback/adoption/native-output storage, and a newly explicit original native terminal-slot resource profile. This profile is not an extra file/member or process: it uses a bounded original native section/mapping object and separately held derivative views by existing admitted original ROOT and O/T custodians. Creating/duplicating/mapping those kernel objects is a material native input and physical charge, not an implicit privilege. Actual Windows HANDLE/section/view protection and Linux mapping/backing/fd/namespace provenance must be source-admitted before use; catalog keys and rights are absent here. Cross-child views require authentic per-child original role/source admission and restricted original producer writes; an address or inherited handle number does not supply that admission.

The creator allocates fixed per-source/per-row slot ranges before covered effects. The sole producer owns its raw call input/output target and publishes completed metadata to its disjoint slot; independent custodians already hold the backing/view. No covered SDK result is sent through the producer endpoint merely to record that endpoint's own result. Sharing by a new channel, unnamed IPC process, default inherited grant or extra persistent member is forbidden. If actual native independent view support is not admitted, the profile is inadmissible before the first covered effect.

Each owner retains original strong managed references in its actual CLR/AppDomain keeper and original native output buffers. Sharing raw bytes does not transfer live CLR object authority or extend native SD pointer validity after the owning process dies. Death before the original copy is complete yields known partial copy plus explicit unavailable original tail. A positive row needing that tail fails; no hash, JSON or reconstructed object substitutes.

## Closed slot and prefix states

Each slot has immutable original source-operation key, invocation/attempt/role/lifetime/row/correlation/ordinal, actual SDK ABI layout binding, finite raw input/output targets, known-field masks and allocation/ownership entries. State is RESERVED -> INPUT_BOUND -> CALL_ENTERED -> CALL_RETURNED -> OUTPUT_KNOWN_PARTIAL_OR_COMPLETE -> PUBLISHED. Interrupted calls retain the greatest original observed state and unavailable remainder. Release records distinguish NO_CALL, RETURNED_SUCCESS, RETURNED_FAILURE and OWNERSHIP_UNKNOWN. Original pointer values are DATA_ONLY; they are not read/free grants.

Publication uses a reviewed platform atomic release/acquire state word in the original mapping; raw output is targeted in place by the actual SDK caller. The source admission must prove the publication operation, memory ordering and its finite physical storage. This is live memory custody, not disk durability. If a publication operation itself requires a covered SDK call, that call receives its own pre-reserved slot; it cannot create an unbounded sequence of auxiliary persistence calls. No implicit heap/spool/default capacity is permitted. Finite exhaustion retains existing original slots, records known exhaustion if capacity allows, and reports incomplete coverage; it never invokes an unreserved recorder allocation.

There is one prefix freeze transition P_PREFIX_CLOSED. It fixes the exact list of completed source-bound records, exact original managed graph references/serialized raw copies, lengths, manifest membership and bytes before package finalization. No reserved/future slot becomes a falsely completed prefix entry. The sole final kind23 readback result and all later effects are terminal suffix. A SHA digest binds only its explicit immutable byte extent; mutable slot regions have no purported final digest. A published slot may be individually hashed from exact known raw bytes, but the hash calculation/verification results are not asserted to be self-included in those bytes.

Private manifest3 is explicitly different from proposed manifest2 and current production v1. Its typed PREFIX_MEMBER entries bind kind23 exact length/hash and original roster/type/source bindings. Its TERMINAL_COVERAGE_PLAN entries bind original slot resource/range, source-operation catalogs, row, custodian and limits, with state DECLARED_NOT_OBSERVED. It contains no future result, receipt, final suffix hash or invented allocation charge. Native SLF7WIT1 and F7_GRAPH_NATIVE keep their own existing encoding; managed/private SDK records cannot be interpreted as those witnesses. Public W/Node v1 and public crypto/index fields remain unchanged; a v1 private reader must reject manifest3. The complete exact private schema, envelope3 one-record carrier and strict v1/v2/v3 source obligations are selected in PRIVATE-MANIFEST3-AND-SDK5-DISPATCH.md for whole review before implementation.

The private manifest3 adds to the complete original mandatory manifest fields exactly `prefix_members` and `terminal_coverage_plan`; it retains the prior kind22 roster/kind23 managed witness definitions, while superseding the self-inclusive native_history_v2 catalogue. `prefix_members` entries have fixed JSON field order `member_key,kind,length,sha256,closed_sequence`; kind23 entries require actual immutable extent and exact source prefix sequence. `terminal_coverage_plan` entries have fixed order `resource_key,owner_key,custodian_key,row,slot_begin,slot_count,operation_catalog_key,layout_catalog_key,lifetime_key,state`; row is0..8, all keys lower32hex bound to actual original16-byte keys, state is exactly `DECLARED_NOT_OBSERVED`. Integers use the existing exact JSON representability bound checked pre-effect. Plan arrays are sorted by row/resource_key/slot_begin, disjoint per resource, and cover only admitted finite slot ranges. Unknown/missing/duplicate/out-of-order fields, fake zero-range coverage, unsupported schemas and aliases to v1 witnesses reject. Actual terminal result bytes/states are ONLY the independently held protocol5 slots (all post-prefix records are LIVE_ONLY; JNL1 cannot checkpoint SDK5), never these plan entries. No future closed sequence/hash is inserted into the plan.

## Persistent and live suffix disposition

SDK5 checkpoints are DISABLED under actual SLF7JNL1: its fixed192-byte records and three events cannot encode SDK5. Every post-prefix record is LIVE_ONLY in the independently held original slot mapping. Existing journal object-persistence events remain their original narrow semantics, not SDK5 checkpoints. Journal freeze/readback and later results remain LIVE_ONLY. This is one finite terminal custody region, not archive generation n+1. No journal revision, second crypto invocation, new index, appended frozen witness, extra journal/member or regenerated package is selected.

The independently held mapping can retain raw slots when a producer process exits if the actual admitted kernel backing and custodian lifetime guarantee that fact. Whole-host/power/device loss is not assumed survivable. Recovery labels each exact immutable prefix extent DURABLE_READBACK_PROVED, each currently original held slot LIVE_ORIGINAL_HELD, interrupted/undefined data KNOWN_PARTIAL, and missing original suffix UNAVAILABLE. The package's authentic signature proves the prefix, not the late slot states. Recovery never promotes a live suffix to durable solely because its bytes match a memory hash.

The original O/T custodian retains its view, pending releases and borrower references until the terminal whole disposition. Covered read/close/free/borrower calls receive original slots before effect. A final close of the last view would destroy the live suffix, so it cannot coexist with a claim that all suffix originals remain held. It is expressly not performed during this profile's evidence lifetime. Held resources are finite and charged for that complete lifetime, with an explicit unresolved-custody status when closure cannot be proved. Later release policy and original result disposition belong the original release owner; no automatic cleanup, reinitialization, D1 reset or positive closure is inferred. This persistent holding changes terminal acceptance and must be approved with the whole contract.

All successful and failed post-prefix calls remain mandatory originals, but universal durable suffix completeness is explicitly not claimed. The complete revised verdict can be PREFIX_DURABLE_WITH_ORIGINAL_LIVE_TERMINAL_CUSTODY, PREFIX_DURABLE_WITH_PARTIAL_TERMINAL_CUSTODY or INCOMPLETE. None is the unchanged FULL_DURABLE_TERMINAL_ACCEPTED verdict. If the product acceptance requires that latter verdict, choose an actually admissible B provider or change the whole acceptance contract; do not rerun A unchanged.
