Durability is a separate fact from completion. A successful WriteFile/send is not a successful full readback or physical durable record. Windows FlushFileBuffers has its own returned BOOL and error, after the flush effect. Linux fsync likewise returns after synchronization; directory-entry durability can require a separate directory fsync. Neither API atomically stores its own returned result in an earlier immutable artifact. [Microsoft FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers), [Linux fsync](https://man7.org/linux/man-pages/man2/fsync.2.html).
