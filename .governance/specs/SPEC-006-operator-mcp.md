# Operator MCP

## Intent
Give Cursor and other MCP clients a local-first operator surface on the Service Lasso runtime: inspect services, secret *metadata*, logs, and later guarded lifecycle actions through the same facades Service Admin uses. This spec binds the production MCP programme already tracked as GitHub `#858`–`#864` and the product leftover `#1067`. It does not invent a second MCP server or a second secrets product.

## Scope
Included:
- One MCP adapter in `service-lasso` that reuses runtime/operator facades
- Read-only tools and resources, including secret metadata without values
- A Streamable HTTP identity slice with OAuth protected-resource discovery, scopes, explicit transport modes, cumulative permission profiles, per-actor/client rate limits, and fail-closed server/Audit policy under `#860` / `AC-6C`
- Complete strict read tools and resources under `#861`, guarded lifecycle and maintenance actions under `#862`, followed by long-running operations and release gates
- Documentation in `docs/reference/operator-mcp.md`

Explicitly out of scope:
- A parallel MCP server in Service Admin, Secrets Broker, or work-agents
- Secret values, tokens, cookies, private keys, recovery material, raw env, or KV get/reveal in MCP output
- Generic shell, unrestricted filesystem, raw config documents, or stdin tools
- Guessing a new transport/identity architecture beyond `#858` / `docs/reference/operator-mcp.md`
- Service Admin MCP settings UI (`lasso-serviceadmin#423` is already closed)
- Canonical demo recycle or keep-alive ownership from this spec
- The inherited `#1067` missing SDK-registration baseline defect; `#860` must keep its identity boundary independently testable

## Acceptance Criteria
- `AC-6A`: The read-only MCP prototype exposes a dedicated secret-metadata tool and resource that return allowlisted metadata only: secret refs, namespace/key, assignment/access-policy status, rotation readiness, and Secrets Broker lifecycle availability. Responses, resources, and tests never include secret values, credential sentinels, env values, tokens, cookies, private keys, recovery material, or absolute workspace/manifest/log paths. Live broker lockout counts stay on the existing telemetry bridge until a later slice; this criterion reports lockout as not queried rather than fetching KV.
- `AC-6B`: MCP protocol plumbing uses the supported official TypeScript SDK with stdio and standards-compliant Streamable HTTP (`#859`). This criterion is not satisfied by handwritten JSON-RPC alone.
- `AC-6C`: Streamable HTTP identity, OAuth protected-resource discovery, scopes, explicit disabled/read-only/guarded modes, per-actor/client rate limits, and server-side policy fail closed (`#860`). Observer credentials cannot mutate state. Permission profiles are derived from cumulative granted scopes, actors come from validated identity rather than tool arguments, and MCP execution stops safely when its Audit event cannot be persisted. Local stdio uses an opt-in credential-bearing adapter connected to the active runtime directly, without starting a competing process or looping back over HTTP.
- `AC-6D`: The complete read-only operator surface covers runtime status, paginated services, health, routes, dependencies, bounded redacted logs, Audit search, updates, drift, recovery, and operations, with strict schemas and structured output (`#861`). `#1067` closes only when this criterion plus `AC-6G` meet the product bar for services, secret metadata, and logs.
- `AC-6E`: Guarded lifecycle and maintenance tools call the shared operator/application facade without HTTP loopback or duplicated lifecycle logic; perform metadata-only preflight; enforce the Observer/Operator/Maintainer/Administrator matrix; and require expiring, actor-, target-, parameter-, plan-, candidate-revision-, and single-use server confirmation for risky actions (`#862`). Confirmed plans bind endpoint allocations, manifest definitions, template bytes, resolved service/provider launch files, recursive setup-step, doctor, stop-override and update-hook execution files, and exact SHA-256 artifact/update candidates, then revalidate those bindings at the relevant materialization or immediate pre-spawn boundary. Launch evidence uses the supervisor's exact resolver, including basename and option-file inputs. Update installation rehashes confirmed archive bytes after pre-upgrade hooks and extracts only the verified in-memory bytes; its confirmation states only the stop and hook subprocess effects executable under the chosen force/policy path. Exact duplicate idempotency keys are claimed across runtime processes and replay the recorded safe result with truthful replay metadata without repeating mutation, while altered or token-like reuse fails closed. Synchronous completions return bounded resulting lifecycle state. Every allowed, schema-denied, policy-denied, skipped, failed, and replayed attempt writes durable Audit with a safe correlation id; terminal Audit outages retain a recoverable pending outcome rather than repeating a mutation. MCP exposes no generic shell, terminal/stdin, raw filesystem, raw configuration, or secret-value action.
- `AC-6F`: Confirmed long-running install and update actions that do not complete within the bounded MCP request budget return a durable opaque operation id without duplicating the underlying guarded action (`#863`). Operation get/list output is actor- and workspace-scoped by default; only Administrator authority can inspect or cancel another actor's operation. Records survive MCP client disconnect and runtime restart whenever the underlying runtime action survives, and expose only strict status, phase, numeric progress, safe summary, timestamps, allowlisted target ids, correlation id, cancellation support, and terminal outcome. Supported cancellation reaches a deterministic terminal state through the shared facade and records durable Audit; unsupported or too-late cancellation is an explicit non-destructive result. MCP request cancellation is propagated where safe without orphaning or repeating the action. Completed operations have documented bounded retention and cleanup. The domain model stays independent of experimental MCP Tasks so a later Tasks adapter does not change launch behavior. No operation state contains raw command output, logs, secrets, credentials, config bodies, absolute paths, or unbounded error text.
- `AC-6G`: Security, redaction, protocol conformance, packaging, and canonical demo acceptance are blocking product gates in the normal CI/release path (`#864`). The gate drives the supported official MCP Inspector and SDK client against Streamable HTTP, proves the opt-in stdio adapter, initialization/version negotiation/notifications/discovery, closed-world schemas, OAuth identity and transport defences, independent actor/client rate limits, the complete permission/confirmation/idempotency/operation/Audit matrix, deterministic limits, and sensitive-output rejection. A staged package is installed into a fresh consumer root and starts the same MCP server without a source checkout on Windows, Linux, and macOS. Canonical acceptance performs safe discovery and representative reads plus one confirmed exactly-once lifecycle action. Each operating-system lane retains one nonempty, exact-SHA-bound, metadata-only evidence artifact containing supported protocol/SDK/Inspector versions and representative result classifications, with no protocol captures, credentials, raw logs, configuration, environment values, local paths, or secret material.

- The Windows native inspector is a published prebuilt managed helper compiled from checked-in C# source. It has no runtime compiler, PowerShell provider, or dynamic-code-generation dependency; the runtime launches the exact package-adjacent executable under the normal product deadline. Its static P/Invoke surface validates returned native buffer bounds before marshalling, closes every native handle, and rejects Toolhelp ancestry drift by querying each process's immutable inherited-parent PID through the same handle used for its creation, image and command evidence. Spawn enrollment rechecks the retained `ChildProcess` handle both before and inside registry mutation. A separate static Windows launcher runs through the absolute trusted System32 Windows PowerShell executable and holds the real service behind unpredictable, phase-specific release/files-bound/continuation/acknowledgement tokens, so pre-created workspace files do not authorize progress. It opens and digest-verifies guarded executable inputs with write/delete sharing denied, retains their canonical handle paths across the final guarded-input confirmation, and fails closed unless an explicitly guarded executable resolves to an approved held file even when the approved set is empty. It then creates the exact target suspended, assigns it to a kill-on-close Job object, and only then resumes it. The product captures initial tree evidence before success, merges every freshly verified descendant into root-exit termination, persists API-stoppable live lifecycle state after failed start or restart containment, uses bounded five-second monitor refresh/retry intervals, and gives real Windows stop convergence a bounded 15-second default while preserving explicit shorter deadline tests. Legacy adoption canonicalizes executable aliases while retaining exact creation-time and command-hash agreement.
- Windows private JSON invokes a separate package-adjacent 5,120-byte managed helper for `ProtectedData.Protect` and `ProtectedData.Unprotect` with null entropy and `CurrentUser` scope. The helper accepts only `protect` or `unprotect`, exchanges bounded canonical base64 through stdin/stdout, emits no stderr or failure detail, clears mutable sensitive buffers, and has no runtime compiler, PowerShell, PATH, file, network or subprocess dependency. Core pins the reviewed executable and canonical provenance digests before sending plaintext, then launches it within the same end-to-end 15-second protection budget; digest checking detects corruption but does not claim to defeat a same-user path replacement race. Existing envelope version/protection tags, atomic commit, SID resolution, owner/SYSTEM ACL enforcement, public error codes and Audit reasons remain unchanged. The fresh-package gate statically rebuilds and byte-compares source/binary/provenance without executing the helper first, proves installed bytes equal the reviewed assets, and leaves the installed guarded action as that hosted lane's first DPAPI execution.
- `.github/workflows/mcp-product-acceptance.yml` runs the source conformance and fresh-consumer packaged acceptance on Windows, Linux and macOS, uploads the three retained artifacts, and requires an aggregate exact-SHA/artifact readback before success.
- `#860` includes local stdio credential handling and smoke evidence. The adapter must reuse the active runtime directly; a second runtime owner or HTTP-loopback adapter would violate the architecture.
