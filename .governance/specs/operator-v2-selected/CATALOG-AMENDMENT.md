# Operator v2 collection authority amendment — pending selection

This additive proposal completes CODECS-AND-STATE.md sections 2 and 4 (lines 27, 57, 59 and 124). The original five selected documents retain their exact historical bytes. This proposal grants no execution, native admission or publication authority. Parent selection is required before the new catalog schema is implemented.

ConfigForm becomes exactly `{serviceId,definitionRevision,modelEpoch,fields,catalogs,availability}`. Field retains its exact six keys. `catalogs` is mandatory, including a genuine empty array. A catalog is exactly `{selector,type,constraints,catalogRevision,entries,slots,readonly,availability}`. Its selector is a versioned collection registry identifier, distinct from an entry selector; initial collection identifiers are `config.files`, `config.templates`, `install.files`, `install.templates`, and `files.roots`. Type is respectively `file_entry`, `template_entry`, or `root_entry`. Install collections are admitted only when the actual materialization capability supports editing. No free dotted traversal or client array index selects a collection.

An entry is exactly `{entryHandle,selector,value,readonly,availability}`. The entry selector is its issued versioned field registry identifier, and must match a field of the same type and constraints in the same form. The entry value equals that field's classified value. An unavailable value is null with unavailable availability; this does not mean an unset value is authoritatively absent. `entryHandle` is nonnull only when a current entry identity is actually held and removal authority can be issued; otherwise it is null. A slot is exactly `{slotHandle,targets,readonly,availability}`. `slotHandle` is nonnull only for a positively admitted insertion slot. The targets array is an issued finite logical target catalog, not a filesystem listing or free path choice. A target is exactly `{targetHandle,sourceHandles,availability}`; sourceHandles is an array of admitted template source handles, empty for file/root slots. Template insertion selects one of that target's sourceHandles. File/root insertion does not accept sourceHandle.

Catalog constraints remain the selected closed structured-entry constraints `{catalogRevision,maxEntries,maxContentBytes?}`; catalogRevision must equal the enclosing catalog revision. maxEntries is an integer 1..128, maxContentBytes is present only for file_entry and is an integer 0..32768. File values are exactly `{targetHandle,content}`; template values exactly `{sourceHandle,targetHandle}`. Root values are exactly `{label,mode,hidden,protected,pathHandle}` with mode read-only/read-write, booleans exact, label at most256 UTF8 bytes. A root slot's targetHandle is compared with the submitted pathHandle, not inserted as an extra root property. Strings/handles obey the selected bounded canonical grammar and existing UTF8/control/duplicate-key guards. File content is classified solely at the typed file_entry.content position and requires the selected classified-input entitlement; key spelling elsewhere never confers content permission.

There are at most128 catalogs,128 fields,128 entries per catalog and128 slots per catalog. Across the form there are at most128 entries,128 slots,128 target rows and128 source handles. Collection target rows and source handles are charged before allocation, as are existing value count/depth/byte limits. The existing64KiB request,256KiB response, depth16 and8192-value envelope bounds remain cumulative; a form exceeding any bound is limit_exceeded, never truncated or silently paged. Catalog selectors are unique; entry selectors are unique across all catalogs and match exactly one Field. All nonnull entry/slot/path/source/target handles are distinct within their authority kind. Duplicate target handles within a slot or source handles within a target are rejected. Registry parent-child collision validation allows only explicitly registered collection-to-entry membership; arbitrary selector collisions remain invalid.

Availability follows the selected exact closed Availability tuple. readonly is boolean and composes monotonically: a readonly form capability/catalog/entry/slot cannot become writable through a child availability flag. Unavailable/corrupt catalogs retain private originals and disclose no guessed entries, slots or targets. Ready catalog membership is backed by complete current held source inventory; an empty ready inventory requires genuine positive completeness. Fields/catalogs that cannot be disclosed under cumulative general/profile/source/manifest policy are unavailable, not permission-scrubbed partial ready inventories.

Private handle records bind kind, exact selector, actor/client, canonical service identity, definitionRevision, canonical generation, modelEpoch, catalogRevision, bounded expiry and original held object/slot identity. Entry removal authority and path/source/target authority are separate kinds and never interchangeable. No handle encodes a public raw path or index; issuance is not native containment proof. Each insertion target must already exist in the actual selected source-declared logical target catalog with held containment/identity evidence. Unknown/new targets require the separately selected source-contract extension described in original line59; absence of that extension does not create guessed insertion authority.

The existing closed operation forms remain `{op:'set',selector,value}`, `{op:'unset',selector}`, `{op:'add_entry',selector,slotHandle,value}`, and `{op:'remove_entry',selector,entryHandle}`. Add/remove selector is the catalog selector. Set/unset selector is a field/entry selector. Add validates the catalog's exact typed value, chosen target/source membership and remaining capacity. Remove validates the exact original entry membership. Unset is allowed only when the actual selector registry declares optionality. No operation interprets a null handle as omission, position or wildcard. Preview binds every handle and original source preimage, catalog revision, generation, epoch, actor/context and candidate digest. Execute rechecks all these bindings under the common actual all-writer publication lock immediately before mutation; expiry, changed membership/generation/epoch, readonly or missing held identity conflicts without publication. Full candidate validateManifest and existing held containment/native-owner obligations remain mandatory. Failed/partial publication preserves the old bytes and recovery journal, never claims removal or insertion from an availability response alone.

Core/TUI shared codecs, forms and reducers must use this exact grammar after selection. Acceptance adds duplicate/cross-kind handle denial, classified content location checks, real empty complete catalogs, stale catalog/generation/epoch/expiry conflicts, readonly composition, source-declared useful add/remove for files AND templates and root entries, and retained corrupt/private originals. This amendment does not relax any existing all46 requirement or source/native qualification gate.
