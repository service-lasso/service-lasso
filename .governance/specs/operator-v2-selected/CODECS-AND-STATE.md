# Codecs and state — complete proposed contract

Status: UNSELECTED v2 policy/schema proposal. This file supplies operative codec/state choices for whole review; none is an implemented wire assertion. Legacy v1 envelope, HTTP audit actor STRING and private identity OBJECT remain distinct. Final source types and route specifications must be generated together after selection; closed schemas below prohibit unlisted properties at every nesting level.

## Common codec and bounds

Every JSON request and response: fatal UTF8 decoder, reject BOM, invalid sequences, lone surrogates, duplicate object keys at any depth, prototype/reserved keys, nonfinite/out-of-safe-range integers, trailing tokens and unknown fields. Count actual UTF8 bytes before parsing. Proposed limits: request65536 bytes, response262144 bytes, nesting16, total object/array values8192, property name128 bytes, public string4096 bytes, public displayName256, display description1024, ID128, summary512. Endpoint-specific limits may be lower and must be advertised exactly; truncation may be applied only to declared display text with truncated=true, never to IDs/revisions/context/binding/schema. Error envelope8192 bytes. Cursor/context local file4096 bytes; preserved existing opaque context contract cannot be silently widened or coerced.

Each string rejects terminal control escape characters and CR/LF for identifiers; displayed log text encodes controls before terminal rendering. Unicode normalization is not applied to opaque IDs, digests, signatures or secret references. Compare identifiers byte-exactly; display Unicode rune/grapheme boundaries do not modify submitted bytes. Numbers have explicit integer/finiteness/range constraints. Date-time is a canonical bounded UTC string validated against the exact supported format; lexicographic equality is never identity authority.

Envelope is exactly {contractVersion,requestId,generatedAt,data}; version='service-lasso-operator.v2', requestId an opaque bounded ID. Error is exactly {contractVersion,requestId,error:{code,messageKey,retryability,fieldErrors}}. retryability='never'|'read_retry'|'new_preview'; fieldErrors <=32 entries {selector,code}, no raw value/message/path. Enumerated code set: invalid_request, invalid_utf8, duplicate_key, limit_exceeded, unsupported_version, unsupported_capability, unsupported_selector, validation_failed, authentication_required, permission_denied, confirmation_required, confirmation_expired, binding_stale, revision_conflict, operation_conflict, operation_unknown, source_unavailable, source_corrupt, snapshot_expired, source_replaced, storage_unavailable, dependency_blocked, ownership_unknown, not_found, internal_error. Code-to-HTTP mapping:400 parsing/type/schema;401 auth;403 permission;404 declared missing resource;409 revision/binding/operation conflict;410 snapshot expired;422 full domain validation;503 unavailable/corrupt/ownership unknown;500 internal_error with no raw text. Exact existing v1 mappings remain unchanged. Absence and unavailable must not share404/empty semantics.

Availability is an exactly-three-key object {supported:boolean,available:boolean,reasonCode:AvailabilityReason|null}; there is no enumeratedCode property. AvailabilityReason is the closed subset of the preceding error-code enumeration: unsupported_capability, authentication_required, permission_denied, confirmation_required, binding_stale, revision_conflict, source_unavailable, source_corrupt, dependency_blocked, ownership_unknown, storage_unavailable. Legal combinations are supported=true/available=true/reasonCode=null; supported=false/available=false/reasonCode=unsupported_capability; or supported=true/available=false with a nonnull reason from AvailabilityReason excluding unsupported_capability. Every other combination, unknown reason, missing key or extra property fails closed. An unavailable unsupported selector is reported through its field error rather than inventing an availability reason. Server schema, client codec, discovery and typed screen reducers share this exact definition. Capability={id,availability,requiredProfile,requiredScopes,confirmationPolicy,bindingRequirements}; profile uses actual permissions domain observer/operator/maintainer/administrator in the actual McpPermissionProfile domain, never infer hierarchy from free string. Scopes are the exact seven supported constants in the closed registry below, including independent logs:read and audit:read; proposed metadata must match current enforcement. Log snapshot acquisition AND continuation require service-lasso:read AND service-lasso:logs:read; audit acquisition AND continuation require service-lasso:read AND service-lasso:audit:read. Both additionally require the current actual profile/source permission and applicable manifest-declared entitlement, cumulatively; none is substituted by another. Discovery must report those denials, server admission and source adapters must recheck them, and clients must use the same generated registry. A valid profile with only general read cannot acquire these snapshots; a special scope without general read/profile/source/declared permission cannot acquire them either. No visible metadata or cursor widens authority. confirmationPolicy='none'|'required'; bindings are a closed list of required revision types. List<=128. Unsupported/unknown scopes/IDs fail closed.

Private actor normalization remains canonical authenticated identity with kind/actorId/clientId/scopes/profile and current ingress authority. Body actor is never authoritative. Public audit actor STRING is an approved presentation of trusted identity, <=128 bytes, with no token or canonical private object. Public projection cannot make actorId/clientId/scopes visible by serializing private state.

### Directed graph read contract (F05; R05/R25/R32)

GraphNode is exactly {serviceId,role,presence,availability}; role='service'|'provider'|'unknown'; presence='present'|'missing'. Canonical serviceId uses the shared bounded ID grammar; no synthetic path, capability name, or guessed provider ID. A present node role comes from validated current source. A referenced positively absent service has presence=missing, role=unknown and supported=true/available=false/reasonCode=dependency_blocked. Uninspectable source is source_unavailable, not a missing node. A present node may have typed unavailable readiness while its structurally valid identity is retained. availability keeps exactly the common three keys.

DependencyEdge is exactly {fromServiceId,toServiceId,kind,state}; kind='service'|'provider', state='satisfied'|'blocked'|'unknown'. Direction is ALWAYS dependency/provider (fromServiceId) → consuming/dependent service (toServiceId), matching Core listEdges. Explicit depend_on gives service edges. Source-resolved requires gives provider edges, with the actual provider service ID; when both relations hold the two kinds remain distinct. Multiple requirements resolving to the same provider deduplicate only the same (from,to,kind). Setup-only relations remain setup metadata; no fabricated setup edge enters this graph. Satisfied requires positively established readiness for that relation, blocked positively established missing/not-ready, unknown unavailable readiness; none establishes stop/remove authority. Missing/ambiguous provider resolution yields typed dependency_blocked before snapshot publication, never a invented source ID. Malformed IDs/edge kinds/contradictory duplicate state yield source_corrupt and retain private original evidence.

GraphPage has the common exact Page keys {snapshotId,sourceRevision,rows,nextCursor,expiresAt,truncated}; rows contains GraphGroup fragments only. GraphGroup is exactly {node,edges,edgeOffset,edgeTotal,complete}; node is GraphNode, edges0..16 DependencyEdge entries all with toServiceId=node.serviceId; edgeOffset/edgeTotal integers0..4096, complete:boolean. Snapshot includes EVERY authorized registered node, including isolated nodes, and positively referenced missing service IDs. Group by toServiceId. Distinct groups sort by canonical serviceId UTF8-byte lexicographic order; edges within each group sort by fromServiceId UTF8 bytes then kind ASCII. Dedup precedes paging; repeated identical edge rows disappear, conflicting duplicates fail. No locale or runtime startup order controls wire order. Graph aggregate source bounds: <=4096 nodes including missing, <=4096 distinct edges, <=4096 incoming edges for one node; crossing a bound yields limit_exceeded before publication. These are projection/snapshot quotas, not native memory-domain changes.

Each group is emitted contiguously across as many fragments as needed: first edgeOffset=0, subsequent offset equals prior offset+edges.length, stable edgeTotal and byte-identical node; complete iff offset+length=edgeTotal. An isolated node is one edges=[]/offset=0/total=0/complete=true row. Nonempty groups never emit zero-edge fragments. limit is group-fragment count1..25, default10 (lower than common pageRows100); each fragment carries at most16 edges and each emitted response also respects response262144/depth16/totalValues8192. Server lowers fragment edge count/page rows as needed before encoding; if even one bounded node+edge cannot fit, limit_exceeded. Never trim identities/edges or set truncated=true to hide omissions: graph truncated always false. Continuation starts at exact next group/offset; page can split a group only using these explicit fields. nextCursor=null only after every group complete. Decoder/reducer rejects offset gaps/overlaps/out-of-order/mixed revision/node substitution, duplicate edge tuples across fragments, false complete or premature null cursor. Partial page state is marked incomplete and cannot authorize dependent/removal planning.

First GET freezes validated topology, node readiness and model epoch into graph sourceRevision under current source publication ownership. Graph sourceRevision is a graph snapshot binding, not per-service metadata sourceRevision or a fresh process-custody claim. Opaque snapshot/cursor binds actual actor, cumulative general read/profile/source/manifest entitlement, graph scope and revision; continuation rechecks authority. Deny whole acquisition if an endpoint required for an edge is outside authorized disclosure; never leak private hidden IDs or silently produce a supposedly complete pruned graph. Genuine empty registered graph is rows=[],nextCursor=null,truncated=false under valid snapshot. Missing registry/unavailable/corrupt reads are typed503, never empty. Expired snapshot410; source replacement or changed graph authority409 source_replaced/binding_stale; no merge with a fresh revision. Core must publish one complete new snapshot, and TUI discards old partial graph on refresh/service/context changes. View labels dependency→dependent, shows provider/service roles, missing/unknown readiness, isolated nodes, incomplete loading and stale/errors. It never reverses arrows or derives destruction authority from graph availability. Server DTO/route schema, generated Go codec, source adapter, reducer, graph keyboard view and operator docs use these same shapes; raw DependencyGraph domain objects are not serialized directly.

### Metadata read/write roundtrip (F06; R07/R11/R12/R33)

ServiceMeta is exactly {serviceId,sourceRevision,favorite,position,availability}. position is null or exactly {x,y}, finite integers -100000..100000. Successful ready read: canonical requested serviceId, nonnull opaque sourceRevision, favorite:boolean, position nullable, availability=true/true/null. Unavailable/corrupt read data uses the same keys with sourceRevision=null,favorite=null,position=null and availability=true/false/source_unavailable or source_corrupt; HTTP503 carries the common typed error instead when no service identity can be safely established. Only ready data grants an expectedRevision. Denied auth returns401/403 without preference state; unknown canonical service404 before metadata lookup. Null favorite is never false. Null position with READY availability means unset layout; null position with unavailable availability is unknown, never a reset. No metadata state is inferred from ServiceSummary, manifest definitionRevision, service-list Page sourceRevision, graph sourceRevision or discovery metadataRevision.

GET /services/:id/meta is the canonical initial read, refresh and restart source. It requires trusted service-lasso:read, minimum observer profile, source disclosure entitlement and every applicable manifest read permission. PATCH additionally requires service-lasso:config:write, minimum maintainer profile and service:configure manifest permission; source/manifest/actor policy compose cumulatively. This prospective preference-only capability explicitly declares confirmation policy none, while config/lifecycle/risky-action confirmation policies stay intact. Discovery and availability project these exact policies; unknown mapping or missing permission denies before metadata access/publication. Positively absent metadata for an existing positively validated service means default favorite=false/position=null, with a server-issued opaque absence revision bound to canonical service generation and validated absence preimage. GET does not create default files or change preference state; any normal Audit maintenance remains disclosed. Metadata file permissions/IO failure, malformed/unknown keys/invalid position/redirected state and mixed revision/state are unavailable/corrupt and retain originals. Existing fractional/out-of-range layout is retained privately and reports source_corrupt until explicit reviewed repair; no normalization-to-null overwrite.

sourceRevision is the metadata source-owner's separate per-service revision, stable for identical validated metadata and generation across normal refresh/restart. It binds the exact current held metadata preimage or verified absence plus canonical generation and persistent publication epoch; it is never fabricated by clients, random on every GET, manifest/list revision or mtime alone. Publication changes it, even if later values return to earlier values (ABA protection). All current direct/legacy metadata writers and restore/repair transactions participate in the common cross-process publication/journal boundary and advance that metadata revision plus modelEpoch. Positively absent preimage tokens are validated again under publication ownership before first creation; concurrent creation/replaced generation conflicts. Legacy state has no revision ledger today: source owner must implement/version/recover this authority without reinterpreting existing manifest revisions or falsely advertising current CAS. Until that mechanism and every writer exist, service_meta_patch is unavailable; v2 GET uses the defined unavailable all-null preference/revision projection rather than invent an initial CAS token; current legacy reads remain separately labeled compatibility behavior.

PATCH /services/:id/meta has exactly {expectedRevision,favorite?,position?}; mandatory nonnull expectedRevision comes ONLY from fresh ready GET of same service/generation. At least one optional field; favorite boolean only (null rejected); position null explicitly resets dependencyGraphPosition or bounded {x,y} sets it. Omitted favorite preserves current favorite; omitted position preserves current layout, matching actual writeServiceMeta compatibility. Empty patch/unknown field/unsafe coordinate denied before any effect. Explicit favorite=false clears favorite. Equal supplied values are a validated no-op: recheck expected revision under lock, retain sourceRevision/modelEpoch and return complete ready ServiceMeta; stale token conflicts even for equal values. Changed values commit private preimage/journal and exact new metadata plus revision atomically, then advance modelEpoch/audit and return complete ready ServiceMeta. Partial commit/reply failure remains reconcilable by fresh GET, never automatic patch retry or guessed success. There is no DELETE/reset-all hidden route or null-favorite reset.

PrePOST metadata form keeps draft and original GET metadata revision; rechecks trusted context/availability, then under server lock rereads canonical generation and exact source revision. Two clients with same expected old revision: one changed write succeeds with new revision, other409 without overwrite; a fresh new revision allows later user-confirmed patch. Preserve unchanged other field across all clients/legacy writers. Fresh GET after PATCH and process/TUI restart must show durable exact preferences and new revision. Client caches metadata separately by connection/context/service/generation, keeps favorites unknown while read unavailable, uses real read state for overview favorite filters/graph layout, rejects stale async responses, retains draft on conflict and asks for refresh plus deliberate edit. Failed/corrupt state never clears local or private retained preference evidence. Metadata is not saved in operation reconciliation records. This schema is shared by route/server generator/Go codec/reducer/forms/docs and C/E acceptance, not a permissive side route.
