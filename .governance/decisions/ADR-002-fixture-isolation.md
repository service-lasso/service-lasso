## Common transaction and authenticated IPC

State order is `provision -> launch -> active -> quiesce -> custody_transfer -> approved_inventory -> copy_verified -> delete -> original_absence -> reset -> copy_readback -> close`. Every transition is monotonically sequenced and bound to one invocation. Failure enters retained/unresolved with no automatic resume. Provisioning/privacy/closure/copy cannot be inferred from a later successful state.

Use separate launcher-created private endpoint pairs for W/M/K, bound to actual held launched process, birth, native identity, exact source/protocol digest and unpredictable invocation nonce. No public listener or caller evidence path. Linux selects private AF_UNIX SOCK_SEQPACKET socketpair endpoints with SO_PASSCRED enabled before launch and per-message kernel SCM_CREDENTIALS and validates sender PID/UID/GID against held live role process, not shared UID alone; unauthorized SCM_RIGHTS reject. Windows selects dedicated anonymous pipe pairs: launcher passes only each role's ends in its suspended child's explicit handle list, closes its child-end copies and retains supervisor ends bound to held child/token/birth proof. Handle noninheritance and process/token/duplication denial are mandatory; a claimed SID field is not authentication. Every capsule/receipt is verified on its retained endpoint; copied/cross-role frames reject. Protocol operations are source-enumerated BIND, LAUNCH_ROLE, ASSERT_READ, QUIESCE, GUARDIAN_TRANSFER, APPROVE, COPY, DELETE, ABSENCE, RESET, COPY_READBACK and CLOSE, with distinct role/state authorization; K cannot request launch/delete/reset and M cannot request arbitrary filesystem mutation. Reject duplicate, extra, out-of-order, oversized, malformed and cross-invocation frames. Define a bounded frame header with magic/version, message enum, sequence and byte length; maximum 64KiB per control/read/error frame. Bind finite source-owned record and total-byte limits to the admitted phase input before launch; overflow fails/unavailable and cannot silently omit inventory/errors or qualify deletion. Reads use bounded offsets/lengths and no seek/write/reopen RPC. Raw secondary error streams use separately bounded private framing and explicit truncated/unavailable states, never silent complete capture. Public output contains only separately reviewed finite schemas; no raw private payload can reach TAP/console.

Approve complete inventory before copy after all writer closure and guardian transfer. Hold owner/type/identity-validated originals and bounded no-follow component traversal. Detect unexpected mounts, substitutions, additions and incomplete inventories. Copy all approved bytes and private raw secondary errors to the separate persistent root, hash/size original held reads, then independently enumerate/read destination and verify exact inventory before any delete. Supervisor retains persistent copy ownership; K retains complete manifest/read capability through post-reset/ENV readback and supervisor natural closure. K independently reads copy bytes through read-only persistent-copy handles issued after verification, with no writable mapping or namespace authority; these remain valid through supervisor natural exit/EOF. Original capsules expire on deletion/retained failure/disconnect, copy capability survives only its explicit retained lifetime, and close/replay/partial-frame failures are retained without minting fresh authority. Owner-mutability stays explicit.

Linux uses descriptor-relative unlinkat only during continuous proven writer exclusion; unlinkat is not inode-conditional. Windows uses the same approved handles for copy and ordinary disposition. Neither path deletes unknown names. Controlled added names or approved-unlink faults preserve remainder, journal exact partial deletion privately and keep complete independent copy; root-not-empty fails. No fresh deletion inventory, recursive rm, retry of unknown objects or success from retained cleanup. Proven original absence, copy verification and existing child/server/managed/accepted-union closure are required before reset. ENV/hook restoration is unconditional; every restoration/guardian/copy/reset/close failure is retained without replacing primary errors.

Linux keeper may receive only read-open sealed memfd evidence with WRITE/GROW/SHRINK/SEAL seals after writable mappings end; FUTURE_WRITE alone is insufficient. Memfd disappears with final reference and is supplemental. Persistent original/copy survive supervisor/keeper failure; do not automatically remove backing, unmount-delete, retire UID/SID or recycle identity while retention remains. Windows copy is SYSTEM-owned private point-in-time verified, not immutable to trusted supervisor/administrator.

API support for the selected channel primitives: [Linux unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html) documents socketpair, SO_PASSCRED/SCM_CREDENTIALS and SCM_RIGHTS; [Windows inherited pipe guidance](https://learn.microsoft.com/en-us/windows/win32/procthread/creating-a-child-process-with-redirected-input-and-output) documents endpoint inheritance and parent-copy closure.
