## Common transaction and authenticated IPC

State order is `provision -> launch -> active -> quiesce -> custody_transfer -> approved_inventory -> copy_verified -> delete -> original_absence -> reset -> copy_readback -> close`. Every transition is monotonically sequenced and bound to one invocation. Failure enters retained/unresolved with no automatic resume. Provisioning/privacy/closure/copy cannot be inferred from a later successful state.

Use inherited private socket/pipe handles created by launcher, explicit peer native identity, unpredictable invocation nonce, exact source/protocol binding and sequence validation; no named public listener or caller-supplied evidence path. Windows uses only allowlisted inherited pipe handles with restricted handle/process custody; Linux verifies peer credentials and invocation UID on its inherited socket. Reject duplicate, extra, out-of-order, oversized, malformed and cross-invocation frames. Define a bounded frame header with magic/version, message enum, sequence and byte length; maximum 64KiB per control frame and finite source-owned record counts. Raw secondary error streams use separately bounded private framing and explicit truncated/unavailable states, never silent complete capture. Public output contains only separately reviewed finite schemas; no raw private payload can reach TAP/console.

Approve complete inventory before copy after all writer closure and guardian transfer. Hold owner/type/identity-validated originals and bounded no-follow component traversal. Detect unexpected mounts, substitutions, additions and incomplete inventories. Copy all approved bytes and private raw secondary errors to the separate persistent root, hash/size original held reads, then independently enumerate/read destination and verify exact inventory before any delete. Keeper retains complete manifest/read custody through post-reset/ENV readback and supervisor natural closure. Owner-mutability stays explicit.

Linux uses descriptor-relative unlinkat only during continuous proven writer exclusion; unlinkat is not inode-conditional. Windows uses the same approved handles for copy and ordinary disposition. Neither path deletes unknown names. Controlled added names or approved-unlink faults preserve remainder, journal exact partial deletion privately and keep complete independent copy; root-not-empty fails. No fresh deletion inventory, recursive rm, retry of unknown objects or success from retained cleanup. Proven original absence, copy verification and existing child/server/managed/accepted-union closure are required before reset. ENV/hook restoration is unconditional; every restoration/guardian/copy/reset/close failure is retained without replacing primary errors.

Linux keeper may receive only read-open sealed memfd evidence with WRITE/GROW/SHRINK/SEAL seals after writable mappings end; FUTURE_WRITE alone is insufficient. Memfd disappears with final reference and is supplemental. Persistent original/copy survive supervisor/keeper failure; do not automatically remove backing, unmount-delete, retire UID/SID or recycle identity while retention remains. Windows copy is private point-in-time verified, not immutable-to-owner.
