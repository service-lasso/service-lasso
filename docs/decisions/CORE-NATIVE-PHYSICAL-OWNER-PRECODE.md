## Physical representation choice and rejection conditions

The proposed parser backend is one original native nonexecuting writable virtual-memory reservation. Its actual OS reservation, commitment, page geometry and guard geometry are part of the original native calibration/object association. The arena's headers, free-extent representation, cell records, live borrower links, indexes, alignment gaps and committed pages are charged within its same admission-resident accounting. The source uses checked integer extent arithmetic; no allocation receives credit before the original allocator/VM operation actually ends and the retained object has no borrower. Page size or alignment cannot be guessed from the host name. OS reservation/commit failures are retained native attempts; they do not enter a libc allocation fallback.

Private records have explicit fixed-width layouts and compile-time layout assertions in the eventual selected source. Cross-process frames use explicit byte codecs, not C++ structure memcpy. Cells identify owner/root/object generations and allocation offset/length, maintain intrusive borrower membership and a serialized state (empty, acquired, close-admitted, close-observed, unresolved, retired). Raw byte windows identify the same original extent and exact subrange. Window acquisition itself reserves its link/control cell before exposure; move and release do not allocate. Every arithmetic bound includes the actual backend rounding and allocator/control extents. Until the exact record layouts, maximum simultaneously retained cells and OS backend are derived below, no positive arena/root factory exists and no numerical control allowance is claimed.

The original native call stack is a retained thread-stack/ABI association. `nativeStackBytes=sizeof(local return values)` in the clock proposal is only a local overlay observation, not a complete SDK/compiler/spill/stack charge. The full original stack reservation, guard, commitment, TLS and source-native call-chain bounds must be independently associated with the sampling/worker thread. SDK internal allocations and returned buffers are separate extents, including error and cleanup paths. A stack cannot be credited again as a new per-call pool or considered ended at function return.

## Exact joins and nonthrowing native transition

The primary owner implements the move-only RootLease, FrameLease and CellLease joins requested by clock54f2. Root enrollment requires the original process lifecycle and source progress graph. Native-frame reservation admits the exact input bytes, maximum original output extent, local-return layout and original retained thread-stack association; it simultaneously pre-enrolls the failure/disposition record. The first source action after a native call obtains its native error and commits the raw result into the pre-enrolled frame without allocation or exception. A thrown std::runtime_error, newly grown string/vector, or newly allocated archive record cannot be this first commit.

The frame retains `nativeCallEntered`, actual scalar result, native error, actual raw handle, process/thread IDs, requested flags, attempt and actual output-body byte count. Scalar-only APIs retain the scalar without inventing an empty successful IO body. An unsuccessful begin-close commits a no-native-call disposition distinguishing not-created, already-attempted and live-borrower refusal. It is not a close success. Actual close is admitted once, records its first native result and never retries from a destructor. Linux EINTR remains unresolved if the original object's disposition cannot be established. Destruction releases only the intrusive borrower link; it neither performs native close nor frees unresolved history.

An original result frame becomes immutable before observation/publication. Clock, namespace and observer borrow the same frame or byte extent rather than copying its bytes into independent arenas. A frame retires only through the existing mandatory archive association, actual ended IO, complete closure/disposition and zero original borrowers. No GC finalizer, null assignment, logical `Budget.closed`, successful function return or hash comparison provides this retirement.
