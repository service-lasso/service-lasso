Core performs original actor authorization and canonical semantics; native storage independently verifies the capsule/catalog/stage correspondence before effects. NQ1 adds a complete native repetition of those semantics without moving actor authorization or source approval to a parser.

No native inflater, ECMAScript Unicode regular-expression implementation, insertion-order JSON tree, native whole manifest validation implementation, or authentic catalog authority wrapper exists in those frozen source interfaces. Existing `Json` uses `std::map`, retains number lexemes and performs sorted compact serialization. Existing `OriginalInputObjectRead` explicitly implements only transferred original IO; its constructor cannot confer CE1 source-owner/publication admission. Production TS catalog is empty. ## Compression implementation selection

Proposed new internal headers implement a native RFC1951 decoder, CRC32, strict gzip wrapper and the complete SLTP ZIP profile. This is a source-owned decoder, with no external library, Node callback or OS subprocess. It has no schema or public interface authority. Its implementation and adversarial cases receive independent whole review. The operation takes immutable compressed views and writes directly into its exact pre-reserved native output allocation, retaining input owners. Stored, fixed-Huffman and dynamic-Huffman blocks all work, including empty blocks/empty output, bit crossings, overlapping distance copies and complete legal code alphabets. Invalid oversubscribed/impossible alphabets, missing end codes, illegal repeats, impossible distances, reserved block/type/code values, truncation, overrun and incomplete termination deny. Exact input consumption is observed, not inferred from output length. CPU progress is checked against the same original deadline without renewal.

Gzip accepts actual TS optional FEXTRA/FNAME/FCOMMENT/FHCRC handling, validates reserved flags and method8, validates header CRC when present, exact single deflate stream consumption, CRC32 and ISIZE, and exactly one final trailer at original EOF. Concatenated streams/trailing bytes deny because the current canonical asset decoder requires the trailer to end the complete asset. TAR independently implements the actual canonical assets profile: checksums/octal/strict UTF8 zero-terminated fields, the allowed first exact commit PAX global record, complete expected directory set, original allowed file set including policy self-member, original mode transformation, length/hash/policy equality, zero padding and at least two zero blocks with wholly zero tail aligned to512. No extraction occurs.

SLTP ZIP implements EVERY predicate of `decodeAdmissionZip`: final22-byte EOCD only, no comment/split disk; exact counts/central boundaries/declared inventory; needed`<=`20; flags exactly0800; methods0/8; no extra/comment/disk; exact regular100644 attributes and no directory bit; identical local/central name, method, flags, sizes, CRC; no holes/overlap/prefix/trailing local records; exact whole compressed input consumption; raw expanded count and CRC; expected path membership and duplicates. Transport mode is always0644; owner final0755 remains a separate materialization property. All existing tighter owner bounds apply: compressed`<=`10MiB, entries`<=`512 and actual maximumFiles, each entry`<=`8MiB, full expanded`<=`64MiB and actual maximumTotalBytes, ratio`<=`100, path depth from actual policy. Integer additions use checked wide arithmetic before range access. Empty stored/deflated files remain supported.

## Ordered JSON, Number and regular-expression dependency decision

Proposed ordered JSON implementation is a native port of the exact strict reader and serializers, separate from the journal's existing `Json`. Object member order is retained, decoded duplicate keys deny, UTF8/surrogate/BOM/trailing/depth/token/member/string-byte bounds remain exactly the current TS contracts. Value construction and scalar conversion are charged. Numbers are binary64 finite values with the same decimal input conversion and ECMAScript shortest-roundtrip output, including negative-zero normalization, exponent formatting and property index ordering. Pretty serialization uses two spaces, empty object/array handling and one LF, with ECMAScript integer-index keys first and insertion order for other keys. Contract canonical hashing reproduces `canonicalJson`'s UTF16 lexicographic key sort followed by ECMAScript enumeration, excludes only contractDigest, and excludes final LF for the semantic digest. Raw pretty equality cannot be replaced with sorted JSON equality or a lexeme-preserving number printer.

The exact reference engine source/Unicode version and finite allocator hooks must be selected and frozen BEFORE implementation. No guessed engine pin is selected here. The review must resolve whether a complete port is feasible under this ownership domain or select a concrete fully source-pinned native engine with equivalent semantics and complete allocator/dependency custody. That alternative requires an amended complete NQ1 packet, not a silent dependency installation.

This dependency decision is concrete and source-level: full language semantics, exact source/Unicode reference, all allocators and original-deadline interruption are required together. Actual implementation must retain backreferences/lookarounds/capture/Unicode escapes/property escapes/casefold/multiline/zero-width/greedy behavior wherever the selected Core contract accepts them. A source/engine version mismatch or unproved valid-input exclusion keeps NQ1 unselected. No max-pattern restriction, regex instruction counter or hidden replacement timeout is introduced.
